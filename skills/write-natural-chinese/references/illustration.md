# 文章配图要有出处，也要有工作

这份文件用于完整文章的配图检索、选择、插入与审核。正文结构稳定以后再读。用户明确不要图片时跳过。

## 先确定图片解决什么问题

逐段找真正需要视觉帮助的位置，不按固定字数插图。

- 人物、地点、产品、历史事件和现实现场需要视觉落点时，检索真实图片。
- 数据关系、时间变化和流程需要精确理解时，优先制作有数据来源的图表或图解，不能拿装饰照片代替。
- 抽象观点只有在具体场景照片能帮助读者理解时才配图。机器人、人脑发光、握手和空办公室一类通用图库照通常没有作用。
- 虚构场景需要视觉呈现时，使用用户提供的素材。只有用户明确要求或同意生成图片时，才使用生成图片，不从互联网找一张真人照片冒充故事人物。

每个候选位置先写清图片要回答的问题、图像类型、检索对象与紧邻的段落。图片没有独立任务就不放。长文通常只需要封面或开头主图，再在少数关键转折处放图；材料确实需要时可以更多。

## 检索实际可用的图片

工具可用时直接检索并取得实际图片结果，不把“建议搜索某某关键词”当成交付。查询要包含具体对象、时间、地点、动作或视觉关系，避免只搜文章标题里的抽象名词。

优先顺序如下。

1. 公共领域或许可清楚的开放资源，例如 Wikimedia Commons 的具体文件页。
2. 条款清楚的图库，例如 Unsplash、Pexels 或用户指定的素材库。
3. 官方发布页、机构图库或产品媒体资料。只有页面明确允许当前用途时才下载或嵌入。
4. 其他网页图片只作为发现线索。找不到作者、原始页面和使用条件，就不能直接转载。

图片搜索结果和缩略图只说明图片存在，不代表获得使用权。打开原始页面核对创作者、许可、署名要求、是否允许修改、商业使用与再发布限制。许可会变化，使用前重新确认。

不能暗示图片中的人物、品牌或机构为文章观点背书。可识别人物不能被放进侮辱、疾病、犯罪、财务困境等敏感语境，除非图片真实记录该事件且当前使用成立。装饰性人物照不能冒充文中当事人。

## 记录来源与许可

每张图片内部记录下列信息。

- 图片标题或准确短说明。
- 创作者或发布机构。
- 原始图片页面链接，不能只留图片文件地址或搜索结果页。
- 具体许可或使用条款及其链接。
- 是否修改、裁切或加字。
- 访问日期。现实页面可能随后变化。

开放许可要求署名时，至少保留标题、作者、来源和许可。即使图库不强制署名，也优先保留创作者与原始页面，方便用户复核。若修改图片，按许可要求说明修改。

找不到使用条件清楚的图片时，继续换来源。确实没有合适素材，可以改用自制图表、征得用户同意后生成原创配图，或者明确交付一项待授权图片，不得把这一项审核成通过。用户要求互联网检索图片时，不能未经同意把任务改成生成图片。

## 把图片放回上下文

图片应当紧跟它所说明的段落，或出现在读者需要视觉理解之前。不要把所有图片堆在文末。

每张图同时准备三样文字。

- 图片说明。告诉读者图中是什么，以及它为什么出现在这里。不要重复相邻段落。
- 替代文本。客观描述画面中与文章有关的内容，方便无法查看图片的读者。
- 图片来源。给出创作者、原始页面和许可。显示文字同样遵守成稿的错别字、冒号、翻案腔与黑话禁令。

交付界面支持直接显示图片时，把实际图片放在目标段落旁边。界面不支持嵌入时，交付可打开的图片文件或受许可支持的原始图片链接，并明确插入位置。不能用无法打开的热链假装已经配图。

## 最后逐图检查

逐张回答下面的问题。

1. 它与相邻段落说的是同一件事吗。
2. 它增加了事实、理解、证据或必要的阅读停顿吗。
3. 人物、地点、时间、产品状态和情绪准确吗。
4. 读者会不会把示意图误认成事实证据，或者把图库人物误认成当事人。
5. 原始页面、作者、许可、说明和替代文本都齐吗。
6. 图片实际能打开，清晰度和比例适合当前版式吗。

有一项答不上来就换图、改位置、补信息或删除，再重新检查全文的图文关系。

没有拿到完整正文时，只能审核图片本身和用户已经说明的放置目的。不能声称整篇文章、逐段图文关系或错别字审核已经通过。
